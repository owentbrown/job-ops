# Profile › About you: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development. Each task is TDD: write the failing test, implement, make it pass, then commit. Steps use checkboxes.

**Goal:** turn Profile › About you into the Profile v2 brand home: insights from existing data, a saved pitch, stories and values, and an AI skill refresh.
**Spec:** `docs/superpowers/specs/2026-11-13-about-you-design.md`. Read it first; it defines every rule, shape and route used below.
**Branch:** `about-you`, off `my-changes`.
**Tech:** TypeScript, Express, Drizzle + better-sqlite3, Zod, React 18, TanStack Query 5, Tailwind v4 with theme tokens, Vitest.

## Ground rules

- Use theme tokens only. The guard test `orchestrator/src/client/no-hardcoded-colours.test.ts` must stay green.
- Commits:
  - Stage only your own files. Never `git add -A`.
  - Never stage `Overview-V2/`, `signature.png` or `.claude/launch.json`.
  - End each message with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No Docker, no live database, no pipeline runs, no push.
- Tests: `npm --prefix orchestrator run test:run -- <paths> --maxWorkers=2`. Two failures in `ApplicationsPerDayChart.test.tsx` are known and expected.
- Before every commit, run `npm run check:types` and `npm --prefix orchestrator run check`.
- Server patterns to copy:
  - service: `server/services/overview/{load,compute}.ts`
  - route: `server/api/routes/overview.ts` and `profile.ts`
  - private-data scoping: `privateDataScopeFilter`
  - LLM JSON call: `createConfiguredLlmService(purpose)` with `jsonSchema` (see `server/services/summary.ts`)
  - usage recording: `server/services/llm/usage.ts`
  - migrations: the `CREATE TABLE IF NOT EXISTS` list in `server/db/migrate.ts`, plus the matching Drizzle table in `server/db/schema.ts`

## Tasks

### Task 1: shared types and starter skills
- Create `shared/src/types/profile.ts` with:
  - the Zod schemas `BrandEntry`, `PitchEntry`, `ValuesEntry`, `StoryEntry`, `SkillsEntry`;
  - the `Theme` enum: delivery, analytics, customer, leadership, influence, failure;
  - `ProfileEntryKind`;
  - `ProfileInsightsResponse`, which holds `strength {total, checks[]}`, `skills[]` (id, label, demandPct, proof, quadrant), `roles[]`, `landing`, `stories` summary, `pitch`, `values`, `brand`, `dataState` ("ok" | "too-early" | "no-resume").
- Export them from the shared types index.
- Create `shared/src/profile/starter-skills.ts`. It holds the 16 groups from the spec, each with `id`, `label` and lowercase `keywords`.
- Tests:
  - the schemas accept good input and reject bad input;
  - starter skill ids are unique.
- Commit: `feat(profile): shared types and starter skills`.

### Task 2: `profile_entries` table and repository
- Add the table to `schema.ts` and `migrate.ts` (spec, Data section), with an index on `(tenant_id, user_id, kind)`.
- Create `repositories/profile-entries.ts` with:
  - `listEntries(scope)`;
  - `getSingleton(scope, kind)`;
  - `upsertSingleton(scope, kind, data)`;
  - `createStory(scope, data)`, `updateStory(scope, id, data)`, `deleteStory(scope, id)`.
- Validate with the Zod schemas from Task 1. Copy the scoping approach from an existing private-data repository.
- Tests against a temp database, using the existing test helpers in `repositories/*.test.ts`:
  - CRUD;
  - singleton upsert;
  - tenant and user isolation;
  - the migration is idempotent.
- Commit: `feat(profile): profile_entries table and repository`.

### Task 3: pure compute
- Create `services/profile/compute.ts`, which exports `computeProfileInsights(input): ProfileInsightsResponse`. Implement every rule in the spec's Compute section exactly:
  - best-fit set and its fallback;
  - demand and proof levels (proof 3 comes from stories);
  - quadrant thresholds: demand ≥ 50% and proof ≥ 2 is "lead"; demand ≥ 50% and proof < 2 is "prove"; demand < 50% and proof ≥ 2 is "hidden"; otherwise "nice";
  - role families, their tags, and templated why/gap text;
  - landing stats;
  - the six strength checks, with fix messages and action ids;
  - `dataState`.
- Keep the helper functions small: `matchSkill(text, keywords)` (case-insensitive, word boundaries) and `bulletHasNumber`.
- `compute.test.ts` covers:
  - each check, with edge values;
  - proof levels 0, 0.5, 1, 2, 3;
  - quadrant boundaries;
  - each role-family tag;
  - the too-early and no-resume states;
  - a realistic fixture shaped like Owen's profile: strategy and ops roles, a product-manager stretch, Sun Life bullets.
- Commit: `feat(profile): insights compute`.

### Task 4: load and routes
- Create `services/profile/load.ts`. It reads the design resume JSON, `searchTerms`, scoped jobs (title, status, suitability score, description, applied at, stage events) and the entries.
- Add routes to `profileRouter`, following the spec's Routes list:
  - `GET /insights`
  - `GET /entries`
  - `PUT /entries/:kind` (singletons only; reject `story` here)
  - `POST /stories`, `PUT /stories/:id`, `DELETE /stories/:id`
- Invalid bodies get a 400 with a message, in the same style as the existing routes.
- Route tests: auth and scoping, CRUD round trip, the insights shape, and validation errors.
- Commit: `feat(profile): insights and entries API`.

### Task 5: AI skill refresh
- Create `services/profile/skills-refresh.ts`. It takes up to 40 best-fit descriptions, each trimmed to 1,500 characters, plus the current skill list.
- It calls `createConfiguredLlmService("scoring")` with a JSON schema `{ skills: [{label, keywords[]}] }`, capped at 20 skills.
- Merge rules:
  - keep `user` items and any item the user hid or renamed;
  - add new items as `source: "ai"`;
  - when a label matches an existing item case-insensitively, update its keywords;
  - set `refreshedAt`.
- Persist through `upsertSingleton(scope, "skills", …)`.
- Record usage the way other LLM calls do, so it shows in Spend.
- Route: `POST /api/profile/skills/refresh`. Return 409 if a refresh is already running for that user (in-memory lock).
- Tests, with the LLM service mocked:
  - the merge rules;
  - usage is recorded;
  - LLM failure returns a 502 and leaves the stored skills unchanged;
  - the lock.
- Commit: `feat(profile): AI skill refresh`.

### Task 6: client API and queries
- Create `client/api/profile-insights.ts` with:
  - `getProfileInsights()`, `getProfileEntries()`;
  - `saveProfileEntry(kind, data)`;
  - `createStory`, `updateStory`, `deleteStory`;
  - `refreshSkills()`.
- Export it from `client/api/client.ts`.
- Add the query keys `profile.insights()` and `profile.entries()`.
- Add hooks `useProfileInsights()` and `useProfileMutations()`. Every mutation invalidates both keys.
- Tests: the hooks call the right endpoints and invalidate both keys.
- Commit: `feat(profile): client API and hooks`.

### Task 7: page and read-only cards
- Rewrite `AboutYouPage.tsx` to compose these components from `pages/profile/about/`:
  - `BrandBanner`, with an initials avatar, chips, `StrengthRing` and an edit button;
  - `PitchCard`, with a 15/30/60 segmented control, "built from" chips and an empty state;
  - `SkillMapCard`, a CSS-positioned 2×2 with axis labels, the explanation line and a screen-reader list;
  - `RolesCard`;
  - `StoryBankCard`, with theme tiles, a dashed empty gap and the top 3 stories;
  - `ValuesCard`;
  - `LandingCard`;
  - `StrengthSheet`, opened from the ring, listing the checks with fix buttons that dispatch to the panels or Document Studio;
  - the existing documents banner.
- Use layout and copy from the mockup board; read `ProfileHome.dc.html` in the artifact, or the spec, for copy.
- Colours come only from tokens. Headings use `font-heading` and `--heading-weight`. Cards use the Card component.
- Empty states as in the spec. Loading uses skeleton cards.
- Tests: each card renders from a fixture `ProfileInsightsResponse` (ok, too-early and no-resume); the ring has its aria-label; the strength sheet lists 6 checks.
- Commit: `feat(profile): About you brand home`.

### Task 8: edit panels
- Build `BrandSheet`, `PitchSheet`, `StorySheet` (create, edit and delete with a confirm), `ValuesSheet` (chips with star toggles and three labelled range inputs) and `SkillsSheet` (rename, hide and keywords, plus a "Refresh with AI" button showing progress, the last refreshed time, a 409 message and errors).
- Wire each panel to the matching card's Edit or Add button and to the strength-sheet fix actions.
- All panels are keyboard-accessible and have labelled fields.
- Tests: each panel saves through its mutation with the right payload; story delete asks for confirmation; skills refresh shows the busy state and calls `refreshSkills`.
- Commit: `feat(profile): edit panels for brand, pitch, stories, values and skills`.
